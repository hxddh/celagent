# celagent 1.0 — 实现合同与验证记录

> 版本 **`1.0.0`**。本文件是 1.0 的实现合同：保证什么、不保证什么、对象怎么排、怎么验证。
> 配套：`docs/celagent-4.1.md`（用户视角）、`docs/architecture.md`（架构）、`HANDOFF.md`（接手）。

## 1. 目标

把持久化单位从 **turn** 改成 **step**，把执行从 TUI 进程搬到可接管的 runtime：

- 已提交的 message / tool call / tool result / compaction 不丢；
- 进行中的工具最多一个 `unknown`，不静默重放；
- 有幂等键的副作用不重复；
- 单写者租约 + epoch，跨机可接管；
- 工作区可快照/恢复；
- 旧格式一次性 `import-v0`，运行时不保留双读。

## 3. 写协议

1. `lease.acquire(session)`：`lease.json` CAS；同机 pid 已死立即接管，跨机等 TTL。
2. 读本地 Pi JSONL，校验 `manifest.head` 是本地 entry 前缀（id + line hash）。
3. 新 entry 按 256 条 / 4 MB 分块；每块写 `If-None-Match: *` 的不可变 segment。
4. `manifest` CAS（`If-Match`）追加 segment + 更新 head。
5. 冲突：重读 manifest；如果远端 head 是本地前缀，重试；分叉则 `LineageMismatchError`，不猜。
6. 成功后清本地 outbox；失败留 outbox，下次启动重放。

`outbox`：`~/.config/celagent/outbox/<session>.json`，写临时文件 + `fsync` + rename。进程 `/quit`、SIGINT、SIGTERM 都先 flush 再释放 lease（拦截 `process.exit`）。

## 4. 工具 journal

Pi 1.5 的 extension：

```ts
pi.on("tool_call", async (event) => {
  const ok = await journal.start(sessionId, event);
  if (!ok) return { block: true, reason: "durable journal unavailable" };
});
pi.on("tool_result", async (event) => {
  await journal.finish(sessionId, event);
});
```

- `start` 先写本地 pending（fsync），再写远端；远端失败 → **block** 工具（fail-closed）。
- `finish` 写结果；远端失败留本地 pending，下次 `reconcile` 标 `unknown`。
- 恢复时：有 start 有 finish → 跳过；有 start 无 finish → `unknown`；没有 start 的 toolResult → 不应存在。

## 5. 租约与接管

- `lease.json`：`{ owner, epoch, expiresAt }`。
- owner = `<hostname>-<pid>`；同机 pid 不存在 → 视为过期，立即 CAS 接管。
- 跨机：TTL 15 秒；心跳 5 秒；接管 epoch+1。
- 每次 append 前 `lease.assert`；旧写者后续 manifest CAS 失败（fencing）。
- 不做并发多写；第二写者得到明确 `SessionLockedError`。

## 6. 工作区

- `workspace snapshot`：`tar -czf` 当前目录，忽略 `.git`/`node_modules`/`.venv`/`dist`/`build`；默认上限 500 MB。
- 对象：`workspace/<sha16>.tar.gz`；manifest 记录 latest。
- `workspace restore`：目标目录非空需 `--force`；解包到 cwd。
- 不是实时同步；容器化 workspace 计划在 1.1。

## 7. 加密

- `CELAGENT_ENCRYPTION_KEY` = 32 字节 base64。
- AES-256-GCM 信封：`{v:1, alg, iv, tag, data}`；manifest/segments/journal/workspace 全部加密。
- 未设 key 读到密文 → `encryption-key-required`，不当作损坏。
- key 丢失 = 数据不可读；跨机必须同一 key；同一 bucket 不混用加密/非加密。

## 8. 迁移

- `celagent import-v0 <id> --yes`：
  - 优先 `sessions/<id>.jsonl`，其次 `sessions/<id>.json`；
  - 旧 JSONL 用 `sanitizeLocalJsonl` 修尾行；旧 turns 用 `jsonlFromTurns` 转换；
  - 写本地 JSONL → `appendFromFile` 建 manifest + segments；
  - 旧对象不删除；目标 manifest 已存在则拒绝。
- 运行时只认 `manifest.json` 的 `v: 2`；旧对象需要 import。
