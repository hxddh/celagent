# celagent 4.1 — Goal Runner 实现合同

> 版本 **`4.1.0`**。本文件是 4.1 的实现合同：保证什么、不保证什么、对象怎么排、怎么验证。
> 4.0.0 的 goal loop 是 Pi 扩展；4.1 把它彻底换成独立 runner。配套：`docs/celagent-4.1.md`、`docs/architecture.md`、`HANDOFF.md`。

## 1. 为什么推翻 4.0.0

4.0.0 把循环放在 agent 的 TUI 里，用 `agent_settled` / `sendMessage` 驱动。审查发现这类问题都来自“宿主”关系：

- Esc 中断被忽略，goal 立刻又发一轮；
- deadline/预算只在 settle 后检查，长命令可以无限超时；
- 验收进程是 detached 的，TUI 死了它还在跑；
- goal 状态被 agent 读写，guardrail 边界模糊；
- goal + delegate 的成本/worktree 没有接上。

4.1 的修法不是加五个补丁，而是换宿主：

> **goal 是一个受 supervisor 看护的循环进程；agent 是它每次拉起的子进程。**

事件时序问题变成进程生命周期问题：超时杀进程组、停止杀进程组、预算轮询、状态只由 runner 写。没有 Pi 扩展、没有 `agent_settled`、没有 answer watcher 跑在 agent 里。

## 2. 对象布局

```text
~/.config/celagent/goals/<id>/
  goal.json         目标/验收/状态/phase/attempts/cost/lastCheck
  GOAL.md           给人和 agent 看的目标与约束
  checks/*.log      每次验收的完整输出
  attempt.json      run --result-file 的最终文本/错误
  output.log        agent 每次尝试的输出
  answer.json       人回答 blocked 问题的内容
  STOP              停止标记（goal stop 写，runner 读）
  attempt.pid       正在跑的 agent 进程组
  check.pid         正在跑的验收进程组

~/.config/celagent/worktrees/<id>/    goal worktree（默认）
sessions/<id>/...                     普通 2.0 session
```

`goal.json` 关键字段：

```json
{
  "id": "goal-...",
  "objective": "把 npm test 修绿",
  "accept": "npm test",
  "status": "running|blocked|done|stopped|error",
  "phase": "starting|checking|attempting|blocked|done|stopped|error",
  "attempts": 1,
  "budgetUsd": 5,
  "maxAttempts": 8,
  "deadline": "2026-11-15T02:00:00.000Z",
  "protect": ["tests/**", "test/**", "**/*.test.*", "**/*.spec.*"],
  "failureStreak": 0,
  "lastCheck": { "exitCode": 1, "hash": "...", "output": "..." },
  "blockedQuestion": null,
  "cost": 0.42,
  "sessionId": "goal-..."
}
```

## 3. 进程模型

```text
tmux supervisor（celagent-<goalId>）
  └─ __goal <id> --cwd <worktree>      ← goal runner
       ├─ 验收：/bin/sh -c <accept>     （独立进程组，超时杀组）
       └─ 尝试：celagent run --session <id> --prompt ... --result-file ... --no-delegate
                 （独立进程组，deadline/预算/stop 杀组）
```

- runner 由 2.0 的 tmux + watchdog 看护；崩溃后拉起同一个 `__goal`。
- runner 不持有 Pi session；每个 attempt 是一个 headless `celagent run`，同一 session 恢复。
- 验收和 attempt 都是 runner 的子进程，**不是** agent 的子进程；runner 能在超时/预算/stop 时杀整个进程组。
- runner 结束时写 `supervisor/<id>.stop`，watchdog 不再拉起。

## 4. 循环

```text
读取 goal.json（status=running）
  ↓
读 manifest.stats → cost/tokens
  ↓
deadline / budget 检查（超了直接 stopped）
  ↓
跑验收（agent 之外）
  ↓ 通过 → done
  ↓ 失败
nextAction：attempts / 同一失败 ×3 / 保护路径 → stopped / blocked / prompt
  ↓ prompt
写 attempts+1、phase=attempting
  ↓
headless celagent run（同一 session；--result-file；--no-delegate）
  ↓ 被 deadline/budget/stop 杀 → stopped
  ↓ 输出 BLOCKED: <问题> → blocked
  ↓ 正常退出 → 回到验收
blocked：等 answer.json；回答后 status=running，回答文本进入下一次 attempt prompt，继续验收/尝试
```

- 每次 prompt 只带最近一次验收输出（截断 6000 字符）。
- baseline 失败不计入 `failureStreak`；只有 agent 尝试后的相同失败才累计。
- 验收通过但保护路径被改 → blocked；回答里“允许/可以/同意/allow/yes”才放行。
- 验收命令固定：runner 从自己读到的 `goal.json` 取，运行中不改；agent 改文件不会改变 runner 内存里的 accept（但见 §8 信任边界）。

## 5. 硬停

| 条件 | 实现 |
| --- | --- |
| deadline | runner 在每轮前检查；attempt/check 的超时取剩余墙钟；到点杀进程组 |
| 预算 | 每 2 秒读 `manifest.stats`；cost ≥ budget 杀 attempt；下一轮 stopped |
| 尝试数 | `attempts >= maxAttempts` → stopped |
| 同一失败 | 相同 `(exitCode, 归一化输出)` hash ×3 → blocked |
| 保护路径 | 每次验收后查 `git status` + `git diff base..HEAD`；命中 → blocked |
| 人工停止 | `goal stop` 写 STOP + 杀 attempt/check 进程组 + 停 supervisor |

- 预算依赖 provider 上报 cost；不报时退化为 attempts/deadline（文档明确）。
- 验收命令的副作用不承诺 exactly-once；要求可重入（测试/typecheck/lint）。

## 6. 接口

```bash
celagent goal start "<objective>" --accept "npm test" \
  [--cwd dir] [--budget 5] [--max-attempts 8] [--max-hours 2] \
  [--protect "tests/**,test/**"] [--in-place]

celagent goal status [id]        # 不带 id 时列出
celagent goal list
celagent goal answer <id> "..."  # 只在 blocked 时
celagent goal stop <id>
celagent goal resume <id>
celagent logs <id>               # 看 attempt 输出 + runner 日志
```

- 默认 worktree + 分支 `celagent/goal/<id>`；`--in-place` 才写当前目录。
- **goal 是 headless**：没有 `attach` 到 goal 的 TUI。人用 `logs` / `goal answer`；需要 TUI 时先 `goal stop`，再 `celagent up <id> --cwd <goal worktree>` 接管同一个 session。
- `goal start` 要求 repo 根目录（或 `--in-place`）；monorepo 子目录不会默默在根跑。
- `goal status` 显示 status/phase/attempts/成本/最近验收/diff/logs。

## 7. 崩溃语义

| 崩溃点 | 恢复 |
| --- | --- |
| runner 被 kill -9 | watchdog 拉起 `__goal`；先清 attempt.pid/check.pid 的残留进程组，再继续 |
| 验收中崩溃 | watchdog 拉起后重跑验收（命令需可重入） |
| attempt 中崩溃 | session 的未完成工具是 `unknown`，不重放；runner 重跑验收，失败再发新 attempt |
| blocked 中崩溃 | 重启后继续等 answer.json，不烧 token |
| `goal stop` | STOP + 杀 attempt/check + 停 supervisor；goal 状态 stopped |
| `goal resume` | 清 STOP、清残留 pid、重启 runner；blocked 保持 blocked，其余置 running |

- `goal.json` 原子写；runner 是运行中的唯一写者。
- `attempt.pid`/`check.pid` 用于 `goal stop` 和 watchdog 重启清理；SIGKILL 后靠下一次启动清理。
- 停止/重启后 session 仍可用 `celagent up <id> --cwd <goal worktree>` 接管。

## 8. 边界

- **goal session 不提供 `delegate`**：attempt 用 `celagent run --no-delegate`。goal 是“单 session 追一个目标”，并行请用 3.0 的 delegate 单独跑。
- **goal 不是沙箱**：agent 以同一用户跑 shell，能改 `goal.json`、celagent 安装、测试/脚本。runner 防的是“模型说 done”，不是恶意 agent；最终仍由人 review diff。
- **验收可被绕过**：agent 可以改 `package.json` 的 test script；runner 记录并显示改动，但最终仍由人判断。
- **headless**：没有 goal TUI attach；`logs` 是主要观察面。
- 不做多租户、跨 goal 记忆、Web UI、自动 merge/push。
- Windows 的进程组终止是 best-effort；4.1 主支持 Linux/macOS。

## 9. 验证记录

自动化：

- `tests/v4-runner.test.mjs`：baseline 通过不跑 attempt；失败自动重试；同一失败 ×3 → blocked、失败变化不误判；blocked 回答后 done；预算/墙钟在 attempt 前停；attempt 被 deadline 杀；验收期间 STOP 不再拉起 attempt；BLOCKED 停下。
- `tests/v4-goal.test.mjs`：验收 exit/timeout、五种守卫、保护路径、状态/prompt。
- `tests/v2-supervisor.test.mjs`：`kind="goal"` 拉起 `__goal`；child kind 仍通过。
- `npm test`：143 tests / 136 pass / 7 skip（2026-11-14，Node 22/26 双跑）。
- `node --check` / `bash -n` / secret scan 全通过。

未在本次环境验证：

- 真实模型 + 真实 bucket 的完整循环（本 orb 没有 bucket/aws/模型 key）。
- 真实长命令的 deadline 杀组、真实 provider 的 cost 上报。
- 真实仓库上 2 个 goal 并行的收益/冲突。

## 10. 与 4.2 的关系

- Ship Pipeline：goal 产出已验证 diff 后开 PR/看 CI；仍不自动 merge。
- Live Workspace：验收从测试扩展到“服务能起、页面能开”。
- 观测：goal 的 Web/URL 状态、历史 attempts、成本趋势。
