# celagent 3.0 — Durable Delegation 实现合同

> 版本 **`3.0.1`**（3.0.0 的测试/CLI 轮询修复）。本文件是 3.0 的实现合同：保证什么、不保证什么、对象怎么排、怎么验证。
> 配套：`README.md`（用户视角）、`docs/architecture.md`（架构）、`HANDOFF.md`（接手）。

## 1. 目标

2.0 让一个 agent 不死。3.0 让它派出去的 agent 也不死：

- 主 agent 用 `delegate` 把独立任务交给子 agent；
- 每个子 agent 是完整的 celagent session：独立 worktree、lease、journal、checkpoint；
- 父进程退出或崩溃，子 agent 继续跑；结果可以再取回；
- 子 agent 在 turn 中间被 kill 只标记 `interrupted`，不重放；
- 人用 `logs` / `send` / `wait` 接管；合并永远由人做。

3.0 不引入 mission、task DAG、coordinator daemon、reviewer 角色或审批状态机。父会话的上下文就是计划；子 session 就是任务。

## 2. 对象布局

会话（对象存储，沿用 2.0）：

```text
sessions/<child>/manifest.json
sessions/<child>/segments/<from>-<to>-<sha16>.jsonl
sessions/<child>/journal/<toolCallId>.json
sessions/<child>/workspace/checkpoints/<hash>.json
sessions/<child>/workspace/blobs/<sha256>
sessions/<child>/lease.json
```

父子控制面（本机 `~/.config/celagent/`）：

```text
delegations/<child>/task.md       任务（只读）
delegations/<child>/state.json    child/parent/status/prompted/promptDone/turns/worktree/branch/baseCommit
delegations/<child>/result.json   status/text/commit/diffStat/tokens/cost/error
delegations/<child>/inbox/*.json  send 的 FIFO 消息
delegations/<child>/output.log    子 agent 可读输出
worktrees/<child>/                git worktree
```

分支：`celagent/<parent>/<child>`，从 `spawn` 时的 `HEAD` 创建。

## 3. 生命周期

```text
delegate.spawn
  → 校验 parent/task/并发上限
  → 创建 worktree + 分支（isolate=false 时省略）
  → 写 task.md + state.json
  → startSupervisor(kind="child")
      tmux: celagent-<child>
      watchdog: __watch --kind child --task ... --parent ...
  → 返回 { session, worktree, branch, baseCommit }

__child
  → prepareSession（materialize + lease）
  → takeNextPrompt:
      inbox 非空 → send 的消息
      未 prompted → task
      promptDone → finalize
      prompted 且未完成 → interrupted
  → session.prompt
  → patched state: prompted=true 之前先落盘；prompt 返回后 promptDone=true
  → 无新 inbox → commit + write result + stop 标记
```

- `state.prompted` 在 prompt **之前**写；`promptDone` 在 prompt **之后**写。
- 崩在两者之间：重启看到 `prompted && !promptDone` → `interrupted`，不重跑。
- `send` 在 running 时只写 inbox，下一个 turn 边界生效；已结束时先清 tmux/watchdog，再以同一 session 续跑。

## 4. 崩溃语义

| 崩溃点 | 恢复行为 |
| --- | --- |
| spawn 后、prompt 前 | watchdog 拉起，`prompted=false` → 正常跑 task |
| prompt 执行中（工具/模型） | 标记 `interrupted`，不重放；人决定 `send("continue")` |
| prompt 返回后、finalize 前 | `promptDone=true` → 直接写 result，不重跑 |
| finalize 写 result 后、stop 前 | 重启看到 result + 无 inbox → 退出 |
| 父 session 崩溃 | 子 agent 不受影响；父恢复后 `delegate list` / `wait` |
| 子 agent 被 kill -9 且无 watchdog | 状态停在 running；`delegate send` 会重启 supervisor |

## 5. 接口

工具 `delegate`（模型）：

```json
{ "action": "spawn", "task": "...", "isolate": true }
{ "action": "wait", "session": "dlg-...", "timeoutMs": 600000 }
{ "action": "send", "session": "dlg-...", "message": "..." }
{ "action": "list" }
```

CLI（人 / 脚本）：

```bash
celagent delegate spawn "<task>" [--cwd dir] [--no-isolate] [--parent id]
celagent delegate list [--all] [--parent id]
celagent delegate wait <id> [--timeout ms]
celagent delegate send <id> "<message>"
celagent ps --tree
celagent logs <id>
```

`wait` 超时返回当前状态并保留 `running`，不是取消。结果里的 `text` 最多 8000 字符；完整内容在 `result.json` 和子会话段里。

## 6. 隔离与合并

- 默认 `isolate=true`：每个子 agent 一个 worktree，只写自己的分支。
- 父仓库不要求 clean；worktree 从 `HEAD` 创建，父会话未提交的改动**不会**带入，spawn 结果会标记 `parentDirty`。
- 子 agent 结束前在自己的分支上提交（`celagent` 身份，仅本地）；返回 `commit` / `diffStat`。
- 子 agent 没有 `delegate` 工具，不能嵌套；没有自动 push；工具权限与 `run` 相同。
- 合并：`git cherry-pick <commit>` 或 `git merge celagent/<parent>/<child>`；冲突由人解决。
- 3.0 不自动删除 worktree；需要时 `git worktree remove --force ~/.config/celagent/worktrees/<child>`。

## 7. 并发与成本

- 并发上限默认 4（`delegate.maxChildren`，1–8）；建议先跑 2 个。
- 每个子 agent 的 tokens/cost 来自自己的 `manifest.stats`，写进 `result.json`；不回写父会话。
- 单个子 agent 最多 20 个 turn（task + send 合计），超过标记 error，防止失控。
- 父会话不设全局预算；先看 `wait` 返回的成本，再决定是否继续派。

## 8. 边界

- 子 agent 是 headless：**不支持 `attach` 到子 agent 的 TUI**；人用 `logs` / `send` 接管。`attach` 仍用于 `up` 会话。
- 子 agent 共享父进程的环境变量（模型 key、桶凭据）；不是安全沙箱。只派发自己信任的任务。
- `isolate=false` 会在父工作区直接跑；只适合只读任务。
- 不承诺 exactly-once：turn 中间崩溃会 `interrupted`，不重放，可能留下半个改动。
- 不做多租户；不做自动合并/部署；不做跨机调度（子 session 可以跨机恢复，但 spawn 在本机）。
- 父子控制面是本地文件；换机器恢复子 session 需要重新建立 delegation 目录，或直接用 `celagent up <child>` 接管会话。
